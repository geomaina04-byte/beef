Section 01

01 Getting the site running on your own computer

This project is a Next.js website. Next.js is a framework (a set of tools) built on top of React, which is what most modern websites are built with. You don't need to understand React deeply to make small changes — this guide will point you to exactly which file to open for most tasks.

What you need installed first

  • Node.js (version 18 or newer) — this is what runs the project on your computer. Download it from nodejs.org if you don't have it.
  • A code editor — VS Code is the standard choice and is free.

Steps to run the site locally

1
Unzip the project folder and open it in VS Code (or open a terminal inside it).
2
Install the project's dependencies — these are all the outside code libraries the site relies on (like the animation libraries). Run this once: 
npm install
3
Start the local development server: 
npm run dev
Then open http://localhost:3000 in your browser. The site will reload automatically every time you save a file.
Tip

Keep the terminal window open while you work — it shows errors immediately if something you typed breaks the code, usually with a clear message and a file name.

Other useful commands

CommandWhat it does
npm run devRuns the site locally so you can see your changes as you work.
npm run buildBuilds the production version of the site and checks for errors (missing files, typos in code, etc). Always run this before sending changes to anyone — if it fails, something needs fixing first.
npm run lintChecks the code for style issues and common mistakes.

Section 02

02 How the project is organized

Three folders matter most. Everything else is configuration you shouldn't need to touch.

app/ — one folder per page (this is what creates the URLs)
components/ — reusable building blocks that pages are made of
public/ — every image, video, and downloadable file
lib/ — small shared helper files (e.g. the team roster data)

The golden rule

Important

In Next.js, a folder inside app/ becomes a real web address. For example, app/about/page.tsx is what you see at beeftrace.co.ke/about. If you want a new page, you create a new folder in app/ with a page.tsx file inside it — you don't need to register it anywhere else.

What "components" means

Instead of writing one giant file for a whole page, the page is assembled from smaller pieces — a Nav component (the top menu), a Footer component, a Hero component (the big opening section), and so on. Each piece lives in its own file in components/. A page file like app/page.tsx is mostly just a list of which components to stack on that page, in order.

Section 04

04 The two loading screens (easy to mix up)

There are two different loading effects on the site. They look similar but do different jobs — it's worth understanding the difference before touching either one.

1. The intro screen — components/BootIntro.tsx

This is the full, cinematic loading screen with the video, the glowing logo card, and the "Skip" button. It only plays once per visit — the first time someone opens the site in a browser tab. It uses the browser's sessionStorage to remember it's already been shown, so refreshing the page or clicking to another page won't show it again until the browser tab is closed and reopened.

2. The page-transition screen — components/TransitionOverlay.tsx

This is the short (roughly half a second) screen with the logo and a thin progress line that appears every time someone clicks a link to go from one page to another (e.g. Home → Technology). It's controlled by two other files working together:

  • lib/transition-context.tsx — keeps track of whether a transition is currently happening.
  • components/RouteTransitionListener.tsx — silently watches every click on the page. If it's a link to another page on this site, it steps in, plays the loading animation, then completes the navigation.
Why it's built this way

Because RouteTransitionListener watches all clicks automatically, you don't need to do anything special when adding a new link or button — the transition screen will just work on it. You never need to manually wrap a link in anything.

Be careful

If you ever need to change how long the intro screen (BootIntro.tsx) stays on screen, search that file for the word minDuration — that's the number (in milliseconds; 1000 = 1 second) controlling the minimum time it stays visible. It's currently set quite long (20 seconds) — worth a second look, since that's a long wait before a first-time visitor sees any real content.

Section 06

06 Updating the Team page

Everything about the team roster lives in one file: lib/team-data.ts. You do not need to touch any page or component to update it.

To edit an existing person

Open lib/team-data.ts, find their entry (each person is a block between { and }), and edit the text between the quote marks. For example:

{
  slug: "amanda-kimani",
  name: "Amanda Kimani",
  role: "Role to be added",   ← change this to their real title
  bio: "Bio to be added.",    ← change this to a short bio
  photo: "/team/amanda-kimani.svg",
  linkedin: "#",              ← replace # with their real LinkedIn URL
  ...
}

To replace a placeholder photo with a real one

1
Get a real photo — a square headshot works best (roughly equal width and height).
2
Save it into the public/team/ folder. Name it something simple, e.g. amanda-kimani.jpg.
3
In lib/team-data.ts, change that person's photo: line from the placeholder .svg file to your new file, e.g. photo: "/team/amanda-kimani.jpg",

To add a brand-new person

Copy one whole existing entry (from the opening { to the closing },), paste it as a new block in the same list, and fill in their details.

Good to know

The search box on the Team page works automatically — it searches whatever name and role text you put in this file. You don't need to configure the search separately.

Section 08

08 Images & videos

Where things live

public/videos/ — all background/section videos + their poster (preview frame) images
public/team/ — team headshots
public/brand/ — logo files
public/logos/ — partner logos (JHUB Africa, JKUAT)

Rules of thumb

  • Videos should be short (10–15 seconds) and under ~3MB — they loop, so length doesn't add value, just load time.
  • Always add a poster image for a new video (a single preview frame, saved as a .jpg) — it's what shows before the video finishes loading, so visitors never see a blank box.
  • Photos on the site currently come from Unsplash (free, credited) — swap them for real BeefTrace photography whenever it's available, in components/FieldGallery.tsx and lib/photos.ts.

Section 09

09 Common tasks, step by step

"I need to change some text on the homepage"

Open app/page.tsx to see which component holds that section (e.g. Hero, Solution, FAQ), then open that file inside components/ and edit the text directly. Text is usually inside quote marks between <p> or <h1> tags.

"I need to add a new page"

1
Create a new folder inside app/, named exactly what you want the web address to be (e.g. app/careers/).
2
Inside it, create a file called page.tsx.
3
Copy the structure of an existing simple page (e.g. app/about/page.tsx) as a starting point — keep the <Nav /> at the top and <Footer /> at the bottom.
4
Add a link to it in components/Nav.tsx (in the LINKS list near the top) and in components/Footer.tsx.

"I need to change a color everywhere"

Open tailwind.config.ts and change the hex value for that color name. It updates everywhere that color name is used across the whole site automatically.

"Something looks broken after my edit"

Look at the terminal window where npm run dev is running — it will usually show a red error message with the exact file name and line number to check.

Section 10

10 Checking your work before sharing it

Before sending your changes to the rest of the team (or a supervisor), run:

npm run build

This is the same check used before every release. It will:

  • Catch typos in code that would otherwise crash the site
  • Confirm every page still loads correctly
  • Confirm every image/video path you typed actually exists
If it fails

Read the first error message from the top — it names the exact file and line. Fix that one, then run npm run build again. Fixing the first error often makes several others disappear too.

Section 11

11 Glossary — plain-English definitions

ComponentA reusable, self-contained chunk of a page (a button, a card, a whole section) saved as its own file.
RouteA web address on the site, like /about. In this project, routes are created automatically by the folders inside app/.
PropsInformation passed into a component to customize it — similar to filling in blanks on a template.
StateInformation a component "remembers" while someone is using the page, like whether a menu is open or closed.
Hook (e.g. useState)A built-in React tool for giving a component memory or reacting to events. You'll see these at the top of most component files.
Tailwind classA short CSS shortcut written directly in the HTML, like text-gold-soft or rounded-2xl, instead of a separate stylesheet.
BuildThe process of checking and packaging the whole site so it's ready to be published online.
DeployPublishing the built site so it's live on the internet at a real web address.

Section 12

12 If something breaks

  1. Don't panic — almost everything here is easy to undo. If you're using version control (Git), you can always go back to the last working version.
  2. Read the error message in the terminal fully before asking for help — it usually names the exact problem.
  3. Check this guide's Common Tasks section for the specific thing you were trying to do.
  4. If you're stuck, share the exact error message (a screenshot of the terminal is fine) with whoever set up the project — that's almost always enough for them to help quickly.
